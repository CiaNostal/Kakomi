## A. レイアウトタブ（UI・機能の調整）

### A-1. 「出力フォーマット」パネルの UI を洗練させる

**要望:**
- アスペクト比の選択が現在はプルダウン（1:1 / 4:5 / 1.9:1 …）でごちゃごちゃしている。
  さらに「カスタム」選択時だけ幅・高さの数値入力欄が別段に出るのも見づらい。
- **Lightroom のようにグラフィカルにしたい**：1:1 なら正方形、4:5 ならその形の長方形、
  というふうに比率そのものの形をアイコン／サムネイルで見せて選ぶ形式。
- より良い UI 案があれば提案してほしい。

**写真の配置・位置調整について（同じ A-1 内）:**
- 「切り抜き位置」「枠内位置」の調整 UI は文字・プルダウンが多くて鬱陶しい。
- グラフィカルに綺麗にクロップできているので、ユーザーがスライダーで微調整することはほぼない。
  → **内部的にはデータ（`cropSettings.rect` のパン、`photoViewParams`）を持ちつつ、UI 上は隠してよい**かもしれない。

**現状:** `index.html` の「出力フォーマット」fieldset に `<select id="outputAspectRatio">` ＋
`#customAspectRatioContainer`（幅/高さ/⇄）。「写真の配置」fieldset に「トリミング（切り抜き範囲）」
（`#cropAspectRatio` select ＋カスタム幅高さ、`#cropOffsetX/Y` スライダー）と「枠内での配置」
（`#photoPosX/Y` スライダー）。同期は `uiController.js` の `initializeUIFromState` / `updateSliderValueDisplays` / `syncOutputAspectUI`。

**検討メモ（暫定）:** 比率ピッカーは、代表比率のミニ長方形ボタン群＋「カスタム」だけ幅高さ入力を出す
セグメント型が候補。切り抜き位置／枠内位置スライダーは撤去し `cropSettings.rect` パンと `photoViewParams`
は crop モード／本体ドラッグからのみ操作、という整理が A-1 後半の要望と整合する。

### A-2. クロップ時に三分割グリッド（3等分線） ✅ 完了（2026-08-29）

**要望:** 枠内が明るく・枠外が暗くなるオーバーレイに、構図調整用の三分割線（rule of thirds）を重ねたい。

**対応:** `canvasRenderer.js` の `drawCropModeOverlay()` に、クロップ窓（`cropScreen`）でクリップした
縦2本・横2本の細線を追加。枠線と同じく黒（`rgba(0,0,0,0.30)` 幅2）→白（`rgba(255,255,255,0.65)` 幅1）の
順に重ね、明暗どちらの写真の上でも見えるようにした。線の濃さは実写での見え方を見て要調整（手触りチューニング項目）。

### A-3. クロップ時に「外側の写真」を回転できる機構

**要望:** crop モード中に、切り抜き前の元画像（枠の外も含む）を回転させたい（水平出し等の用途）。

**検討メモ（暫定）:** `cropSettings` に回転角を持たせ、`layoutCalculator` で
「回転した元画像から矩形を切り出す」計算にする必要がある。`drawCropModeOverlay` の
`whole` 描画にも回転を反映。中規模の改修。crop 矩形と回転の相互作用（回転後にはみ出す扱い）を要検討。

### A-4. クロップ後に写真をキャンバス内で回転できる

**要望:** crop 確定後、select モードで写真自体をキャンバス内で回転させたい。

**検討メモ（暫定）:** テキストの回転ハンドル（`textHandleStore` / `interactionRegistry` の回転対応、
`utils/geometry.js` の `rotatePoint`）と同じ仕組みを写真にも適用する案。A-3 とはレイヤーが違う
（A-3＝切り出し元の回転、A-4＝出力枠内での写真の回転）ので両方必要か・片方でよいかを整理する。

### A-5. クロップ確定のクリック対象を「キャンバスの外」まで広げる

**要望:** 現在は「クロップ枠の外 **かつ** キャンバスの中」をクリックで確定。キャンバスの外側の余白
（`.canvas-area`）クリックでも確定できるようにしたい。

**現状:** 確定は `previewCanvas` の `pointerup`（`canvasInteraction.js`、`cropExitCandidate`）でのみ検出。
キャンバス外は別要素なのでイベントが来ない。

**検討メモ（暫定）:** `.canvas-area` かドキュメントレベルに「crop モード中だけ有効な pointerdown リスナー」を
足し、`previewCanvas` の外側がクリックされたら `exitCrop()`。既存の選択解除（キャンバス外クリックで
`selectedId = null`）との整合に注意。**難しければ要相談**とのこと。

### A-6. select モードのホイールで余白変更する機能を **削除** ✅ 完了（2026-08-29）

**要望:** レイアウト調整の select モード時にホイールで余白を変えられる機能は不要なので消してよい。

**対応:** `canvasInteraction.js` の `wheel` リスナーを丸ごと削除し、`photoAdapter.commitMarginDelta()` と
定数 `MARGIN_WHEEL_STEP` も撤去した。現在 `previewCanvas` に `wheel` リスナーは無い。
B-2（背景タブでホイール→背景拡大）を実装するフェーズ1で、「開いているタブでホイールの用途を切り替える」
設計として `wheel` リスナーを復活させる想定。

## C. フレームタブ

### C-1. 超楕円スライダーを「体感で等間隔」にする

**要望:** 超楕円の次数 n をスライダーで変えると、特に n=3〜10 で形が変わりすぎる。
n が高いと変化が少なく、低いと急激。バックエンドは n 1パラメーターのままで、
**UI 上はユーザーから見て等間隔に丸くなっていくように見える独自パラメーター（非均等の刻み幅）**にしたい。

例（ユーザー提示のイメージ）:
- 3〜4 の間：0.2 刻み（3.2, 3.4, 3.6, 3.8, 4.0）
- 4 以降：0.25 刻み（4.25, 4.5 …）、さらにその先は 0.5 刻み

**現状:** `frameSettings.superellipseN`（`uiDefinitions.js` `superellipseN: { min: 3, max: 40 }`）、
`frameRenderer.js` の `createSuperellipsePath`。

**検討メモ（暫定）:** UI スライダーを 0〜1（or 0〜100）の「丸さ」パラメーターにして、
`n = f(slider)` の非線形マッピング関数を1つ用意する（低次は細かく、高次は粗く）。
状態には引き続き `superellipseN` を保存。`n` から逆算してスライダー位置を復元する必要があるので
マッピングは単調＆可逆にする。区分線形テーブルか、`n = 3 + a * slider^k` のような式。

### C-2. フレーム（影）タブを開いているとき、影のオフセットをドラッグで動かす ✅ 完了（2026-08-29）

**要望:** 影タブに「オフセット」パラメーターがある。フレームタブ（影のセクション）を開いているときは、
**プレビュー上で影の部分をマウスドラッグして影の X/Y オフセットを直接動かせる**ようにしたい。
写真本体をドラッグして動かすのはレイアウトタブのときだけでよい。

**対応:** 新設 `js/interaction/adapters/shadowAdapter.js`（`shadowParams.offsetX/offsetY` を写真短辺基準%で
操作、-25〜25 でクランプ、0.1%丸め、`backgroundAdapter` と同じ `getValue`/`computeChanges`/`commit` パターン）。
`canvasInteraction.js` の pointerdown が `tabManager.getActiveTab()` を見て、「フレーム」タブ表示中かつ
`frameSettings.shadowEnabled === true` のとき、写真本体（テキスト以外）のドラッグを `shadowAdapter` へ振り替える。
影が無効なときは何も起こさない（写真位置ドラッグへフォールバックしない）。選択状態は変えず、ガイドスナップもしない。
モードを示す UI（カーソル・ヒント文）は出さず、開いているタブ自体を手がかりとする。

## D. 文字タブ — テキスト追加まわりのワークフロー再設計

**総論の要望:** テキスト追加まわりのアクションが洗練されていないと感じている（ユーザー自身もまだ
うまく言語化できていない）。**「なぜ現在のワークフローが洗練されていないのか」をまず言語化した上で、
改善案を提案してほしい。**

### D-1. テキスト追加のフロー

**要望:** 今は「撮影日」等を選択 →「表示する」チェックボックス ON → 表示される → その後編集、という順。
本来は逆で、**テキスト内容を打ち込んでから「テキスト追加」ボタンで画面にポンと追加される**のが自然では。
（自由テキストのイメージ。撮影日 / Exif も含めた導線として評価・検討してほしい。）

### D-2. 固定表示位置（右下・左下など）を UI から消す ✅ 完了（2026-08-29）

**要望:** 9点（or 6点）の固定アンカー位置設定はほぼ使われていない。内部的に残ってもよいが、
UI からは消してよい。位置はドラッグで決めるので不要。

**対応:** `uiController.js` の `renderTextLayerSettingsPanel()` から `<select id="textLayerPosition">` の
行・初期化・イベント配線と定数 `TEXT_POSITION_OPTIONS` を削除。`textSettings.*.position`（既定は
撮影日=`bottom-left`／Exif=`bottom-right`／自由テキスト=`middle-center`）はデータモデル・プリセットに
そのまま残り、`textRenderer.js` の `calculateTextPosition()` がオフセットの基準アンカーとして使い続ける。
UI を消しただけなのでプリセットの移行は不要。

### D-3. 設定項目の共通化

**要望:** フォント・サイズ・透過度・表示位置・回転などは、撮影日 / Exif情報 / 自由テキストで
バラバラに選ぶのではなく **全テキスト共通の設定**にして、場合分けするのは「表示する内容
（撮影日 / Exif / 自由テキスト）」だけにしたい。

**現状:** 2026-08-26-3 のセッションで UI 層は既にかなり統合済み（`#textLayersList` ＋
`#textLayerSettingsPanel`、`uiController.js` の `FIXED_TEXT_LAYERS` / `resolveTextLayer` /
`renderTextLayerSettingsPanel`）。ただしデータモデルは `textSettings.date` / `.exif` / `.customTexts[]`
と分かれたまま（`spec.md` 11.5 節「文字レイヤーのデータモデル統合（見送り）」）。D-3 を素直にやると
このデータモデル統合（`kind` 付きの単一配列化）が視野に入る。既存 localStorage プリセットの
移行が必要になる点は要注意（クロップの `migrateCropSettings` と同じ考え方で移行関数を用意する手はある）。
