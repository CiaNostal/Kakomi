# 開発セッションログ: パネル開閉時の「画面全体がガクッと下がって戻る」不具合の修正 ＋ ログのリネーム（2026-08-28）

`docs/session-log-2026-08-27-7.md`（フェーズ6）の続き。フェーズ6 の実装確認後、ユーザーから
**「レイアウトタブを閉じて開くと、一瞬 画面全体（キャンバス含む）が下にガクッと動いて、また元に戻る」**
という報告があり、調査 → 原因特定 → 修正した（§1–4）。あわせてセッションクローズ時に、
これまで日付が先行していたセッションログを実日付へ一括リネームした（§6）。

## 1. 現象の計測（`kakomi-devtools/panel-jump-repro.js`）

画像ロード後、レイアウトタブを収納 → 320ms 後に展開し、その間 `requestAnimationFrame` ごとに
`.app-container` / `.app-shell` / `.tab-content-area` / `.canvas-container` の高さ・`#previewCanvas` の
画面上 top・`scrollY` を記録した（ビューポート 1280×800）。

**収納フェーズ（パネル幅 360→1px）**: `.tab-content-area` の `scrollHeight` は **746 のまま**、
`.app-container` の高さは **802 のまま**。安定。

**展開フェーズ（パネル幅 0→360px、0.3s トランジション）**:
- 展開開始の数フレーム（パネル幅 ≈ 1px）で **`.tab-content-area` の高さが 746 → 1815 に跳ね上がる**。
- `.app-container` が **802 → 1871**、`.canvas-container` が **698 → 1767** に膨張。
- キャンバスのビットマップ寸法（`canvas.width/height`）は変わらないが、1767px の箱の中央に置かれるため
  `#previewCanvas` の画面上 top が **81 → 616**（約 535px 下がる）。
- トランジションでパネル幅が 1→110→164→250→301→318 と広がるにつれ、内容が
  1815→1742→1136→934→764→746 と縮み、+約 200ms で `.app-container` が 802 に戻る。

出力アスペクト比・画像の有無に関係なく毎回再現。`scrollY` はほぼ 0 のまま（`<body>` はスクロール
コンテナではない）だが、ページ全体が縦に伸びてキャンバス以下がまとめて下へずれ、すぐ戻る。
これがユーザーの言う「ガクッと下がって戻る」。

## 2. 原因

- `tabManager.js` はパネル展開時、`.tab-content-area` の CSS `width` を `0 → 360px` にトランジションさせる。
  その途中、**パネル幅がほぼ 0 の状態で中身（`.tab-pane`＝比率タイル群・スライダー等）がいったんレイアウトされる**と、
  各要素が1行ずつ折り返して縦に約 1800px まで伸びる。
- `.tab-content-area` は `overflow: hidden auto` を持つが、**高さの上限がない**。フレックス連鎖
  （`.tab-content-area` → `.app-shell`〈`flex:1; min-height:0`〉→ `.app-container`〈`min-height:100vh`〉）の
  どこにも「ビューポート高で頭打ちにする」制約がないため、その一時的な高 ~1800px が
  `.app-container`（`min-height` なので下に伸びられる）まで伝播し、同じフレックス行にある
  `.canvas-area` / `.canvas-container` も一緒に膨張する。
- 収納方向（360→0）で膨らまないのは、ブラウザが既存レイアウト（360px 幅・746px 高）を保持したまま
  `overflow-x: hidden` でクリップするため。展開方向は極小幅から新規にレイアウトするので min-content 高が跳ねる。

これはフェーズ4 の既知の不具合 G-1（`.app-container` が下方向に伸びられる素地）と根が同じ。G-1 は
`#previewCanvas` の border を outline 化して当座を止めたが、「レイアウトが下に伸びられる」素地は残っていた。

## 3. 修正

**デスクトップの3カラム時だけ、アプリシェルの高さをビューポートに固定してクリップする。**

```css
@media (min-width: 1025px) {
    .app-container {
        height: 100dvh;
        min-height: 0;
        overflow: hidden;
    }
}
```

- 内側の `.tab-navigation`（`overflow-y: auto`）・`.tab-content-area`（`overflow: hidden auto`）・
  `.canvas-area`（`overflow: hidden`）はもともと各自 overflow を持つので、はみ出しは各領域内で処理される。
  パネル内容が一時的に縦に伸びても `.app-container` は 100dvh のままで、ページ全体は動かない。
- 幅 1024px 以下では `@media (max-width: 1024px)` で `.app-shell` が縦積みになり、
  ヘッダー＋横並びレール＋パネル（`max-height: 40vh`）＋キャンバス（`min-height: 300px`）で
  ビューポートを超えることがあり全体スクロールが要る。そこでは **この固定をかけない**
  （`min-width: 1025px` にスコープ）。ユーザーが過去に経験した「CSS で高さ固定 → 縦積みが崩れる」を避ける。
- 副次効果として G-1 の残っていた「`docSH` が `clientHeight` より 2px 大きい」も解消。

## 4. 検証

- **`panel-jump-repro.js`**: 修正後、画像なし／1:1／4:5／16:9 いずれの収納→展開でも `.app-container` は
  ビューポート高（800）のまま。膨張・ずれ・スクロールゼロ。
- **レスポンシブ**（画像ロードして各幅で計測＋スクリーンショット）:
  - 1280 / 1100（≥1025）: `.app-container` overflow=hidden、高さ=ビューポート、ページ非スクロール、
    キャンバスは枠内に収まる。
  - 1024 / 900（≤1024・縦積み）: overflow=visible（固定なし）。内容はビューポート内に収まり、
    必要なら全体スクロール可。レイアウト崩れなし。
  - 768（縦積み）: `scrollHeight > clientHeight` で全体スクロールが正常に効く。ヘッダー〜キャンバスまで
    スクロールで全部到達できる。
- **回帰**: `panel-jump-repro.js` 追加のほか、`phase2` 19/19・`phase3` 13/13・`phase4` 20/20・
  `phase5` 25/25・`phase6` 33/33・`g1` 13/13。`creep-repro.js` は 4:5 / 1:1 / 89:127 とも `stable`
  （キャンバスがコンテナ高いっぱいを使うようになり、寸法は変わったが安定）。
